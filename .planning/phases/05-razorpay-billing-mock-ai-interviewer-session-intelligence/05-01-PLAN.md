# Plan 05-01: Resume & Document Vault with PDF/DOCX Text Extraction

## Objective
Implement the Resume & Document Vault on the Next.js 15 web platform, allowing candidates to upload PDF and DOCX resumes (up to 10MB), automatically extracting raw plain text server-side using `pdf-parse` and `mammoth`, storing files securely in Supabase Storage with Row Level Security, and making the active resume context accessible to the desktop copilot HUD `PromptEngine`.

## Requirements Covered
- **WEB-02**: Document & Resume Vault supporting PDF and DOCX uploads (max 10MB) with server-side text extraction and secure Supabase Storage.

## Dependencies & Packages
- In `apps/web`:
  - `pdf-parse`: Server-side PDF text parser.
  - `mammoth`: Server-side DOCX text extractor.
  - `@types/pdf-parse`: TypeScript types for pdf-parse.

## Tasks

### 1. Install Parsing Packages
- In `apps/web`, install `pdf-parse`, `@types/pdf-parse`, and `mammoth`.

### 2. Implement Server-Side Text Extraction Utility
- Create `apps/web/src/lib/extractor.ts`:
  - `extractTextFromBuffer(buffer: Buffer, mimeType: string): Promise<string>`
  - Handles `application/pdf` via `pdf-parse`.
  - Handles `application/vnd.openxmlformats-officedocument.wordprocessingml.document` (and standard `.docx` types) via `mammoth.extractRawText({ buffer })`.
  - Cleans and normalizes extracted whitespace, retaining section structure (Experience, Education, Skills, Projects).

### 3. Implement Supabase Storage Bucket & Vault Upload API
- Ensure Supabase Storage bucket `resumes` is configured with public access disabled and user RLS policies.
- Create Next.js API route `apps/web/src/app/api/vault/upload/route.ts`:
  - Validates authentication via Supabase SSR client (`auth.getUser()`).
  - Accepts `multipart/form-data` with `file` (max 10MB) and optional `target_role` / `custom_instructions`.
  - Validates MIME type and file size.
  - Runs `extractTextFromBuffer` on file buffer.
  - Uploads file buffer to Supabase Storage `resumes/${userId}/${Date.now()}_${filename}`.
  - Inserts row into `documents` table:
    - `user_id`: Authenticated user ID.
    - `name`: Clean original filename.
    - `file_path`: Storage path in Supabase bucket.
    - `file_type`: MIME type.
    - `file_size`: Integer byte count.
    - `extracted_text`: Extracted plain text string.
    - `is_active`: Set to true (marks this as active resume, updating older resumes to false).
  - Returns JSON with document record and character count.

### 4. Implement Active Resume Context API Route
- Create `apps/web/src/app/api/vault/active/route.ts`:
  - Fetches the active resume document (`is_active = true` or most recent) for the authenticated user.
  - Returns `{ id, name, extracted_text, custom_instructions, updated_at }`.
  - Supports bearer token or session cookie authentication so the desktop copilot can retrieve it seamlessly.

### 5. Build Document Vault Web UI
- Build `apps/web/src/app/dashboard/vault/page.tsx`:
  - **Drag-and-drop file upload zone** with visual feedback, progress indicator, and file type validation badges (PDF / DOCX, max 10MB).
  - **Active Resume Showcase**: Displays the currently active resume with badge, word count, character count, and collapsible full extracted text preview.
  - **Document History List**: Table/cards of uploaded resumes with upload timestamp, file size, "Set as Active" toggle, and "Delete" button.
  - **Custom Prompt Directives Manager**: Form allowing candidates to specify target role (e.g. "Senior Staff Distributed Systems Engineer"), target company (e.g. "Google / Stripe"), and custom prompt instructions (e.g. "Answer in STAR format; highlight Golang, Kubernetes, and high-concurrency architecture").

### 6. Wire Desktop Context Sync
- In `apps/desktop/src/renderer/src/services/promptEngine.ts`:
  - Connect `promptEngine.setCandidateContext(...)` to pull active resume text and custom instructions from `/api/vault/active` when the user authenticates with `copilot://auth`.

## Verification Criteria
1. Successfully uploads a test PDF and DOCX file.
2. Extracts plain text accurately with preserved sections.
3. Successfully stores file in Supabase Storage and records metadata in `documents`.
4. Web UI shows preview of extracted text and lets user toggle active resume.
5. `/api/vault/active` endpoint responds with the active resume text.
