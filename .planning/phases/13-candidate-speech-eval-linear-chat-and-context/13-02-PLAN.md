# Plan 13-02: Candidate Speech Intelligence & Native Multi-Turn Groq Message Array

## Objective
Upgrade speech processing to detect topics and clarifications from candidate speech (e.g. *"Okay, so you are asking about how to design rate limiter"*), trigger instant AI answers for those topics, evaluate candidate answers in real-time with feedback and next points, and refactor the context pipeline to use native OpenAI/Groq multi-turn message arrays with clean deduplication.

## Key Implementation Steps

### 1. Dual-Channel Speech Intelligence in `questionDetector.ts`
- Process both `interviewer` and `candidate` transcripts.
- When `message.speaker === 'candidate'`:
  - **Clarification / Topic Detection**:
    - Detect patterns where the candidate clarifies the question or specifies a problem to solve:
      - e.g., `so you are asking about (.*)`, `how to design (.*)`, `let's design (.*)`, `can we solve this with (.*)`, `is the question (.*)`, `clarify whether (.*)`
    - When detected: Emit a topic question immediately via `onTopicDetected` or `onQuestion` with source `'candidate'`.
  - **Candidate Answer Evaluation**:
    - If candidate has spoken substantive words (> 6 non-filler words) after an interviewer question / problem was presented:
      - Debounce candidate speech (1500ms after last candidate utterance).
      - Emit an answer evaluation event (`onCandidateAnswer`) containing the candidate's spoken text and the current question context.

### 2. Real-Time Answer Evaluation in `aiAnswerEngine.ts`
- Add `evaluateAnswer(question: string, candidateSpoken: string, history: ConversationTurn[])`:
  - Calls Groq with a structured evaluation system prompt:
    ```
    You are an expert technical interview evaluator.
    The candidate just answered the interviewer's question out loud.
    Evaluate the candidate's spoken response crisply in under 4 lines:
    ### EVALUATION & NEXT STEPS
    - **Strong Points**: (1 bullet on what the candidate answered well)
    - **Missing / Blindspots**: (1 bullet on crucial edge cases, scale constraints, or algorithms missed)
    - **What to say next**: (1-2 punchy sentences to say out loud right now)
    ```
  - Streams tokens into an `ai_evaluation` message in `LiveCopilotFeed.tsx`.

### 3. Native Multi-Turn Groq Message Array in `promptEngine.ts` & `aiAnswerEngine.ts`
- In `promptEngine.ts`:
  - Add `buildMessages(question: string, history: ConversationTurn[], mode: 'solution' | 'evaluation'): GroqMessage[]`
  - Replaces monolithic user string concatenation.
  - Builds an alternating array:
    ```json
    [
      { "role": "system", "content": systemPrompt },
      { "role": "user", "content": "[Interviewer]: Can you design a rate limiter?" },
      { "role": "assistant", "content": "### High-Level Architecture..." },
      { "role": "user", "content": "[Candidate]: I would use a token bucket algorithm with Redis..." }
    ]
    ```
  - **Context Hygiene**:
    - In `injectSolvedCodeContext`, replace the active code slot cleanly instead of repeatedly appending to `customInstructions`.
    - Limit history window to the last 8 relevant turns to prevent token bloat and latency.
- In `aiAnswerEngine.ts`:
  - Pass the structured `messages` array directly in the payload to Groq API (`https://api.groq.com/openai/v1/chat/completions`).

### 4. Wire Callbacks in `LiveCopilotFeed.tsx`
- Subscribe to:
  - `questionDetector.onQuestion`:
    - Append `interviewer` (or `candidate`) question message to `messages`.
    - Append placeholder `ai_solution` message to `messages`.
    - Trigger `aiAnswerEngine.generateAnswer`.
  - `questionDetector.onCandidateAnswer`:
    - Append placeholder `ai_evaluation` message to `messages`.
    - Trigger `aiAnswerEngine.evaluateAnswer`.
- Ensure all token streams update the appropriate message by `id`.

### 5. Update Tests in `question-detector.test.cjs`
- Add test assertions for:
  - Candidate topic clarification: `"Okay, so you are asking about how to design rate limiter"` correctly detected.
  - Candidate answer evaluation trigger on substantive candidate speech.
  - `buildMessages` produces valid alternating `GroqMessage` objects with system prompt and deduplicated active code context.
