# Plan 10-02: Vision Code Window Continuous Canvas & Exhaustive C++ Code Generation

## Objective
Convert `VisionSolutionCard.tsx` into a seamless, full-height continuous canvas where Intuition, C++ Solution Code, and Complexity/Edge Cases flow together as one cohesive document without enclosing card boxes. Concurrently, upgrade the Groq Vision prompt and token allowance to guarantee full, runnable, end-to-end C++ code generation (no abbreviated 5-line snippets or omitted code).

## Context & User Feedback
- Current issue: Code window wraps the solution in an outer card box, and code generation produces very few lines or brief snippets.
- User feedback: *"also in code window ... soultion is in very few lines ... make it complete anvas like intution aand edge cses"*.

## Key Implementation Steps

### 1. Unified Continuous Canvas in `VisionSolutionCard.tsx`
- Remove the outer card wrapper (`background: 'rgba(10, 15, 29, 0.75)'`, `border: 1px solid rgba(59, 130, 246, 0.25)`, `borderRadius: '10px'`).
- Dedicate 100% of the active body area to the flowing document canvas.
- Maintain top action controls (Solve button `Ctrl+Shift+H`, Copy Code, Back to Copilot `Ctrl+Shift+L`) cleanly floating in a minimal top row.

### 2. Full Complete C++ Code Generation in `visionSolver.ts` & Web Route
- Update system prompt in [visionSolver.ts](file:///c:/Users/acer/Desktop/parakeet%20ai/apps/desktop/src/renderer/src/services/visionSolver.ts) and [route.ts](file:///c:/Users/acer/Desktop/parakeet%20ai/apps/web/src/app/api/copilot/solve-code/route.ts):
  - Strictly mandate **complete, runnable, production-quality C++ code**.
  - Require all necessary headers (`#include <vector>`, `<string>`, `<unordered_map>`, `<algorithm>`, `<iostream>`, etc.).
  - Require full class / struct definitions if custom types are needed (e.g. `TreeNode`, `ListNode`), and complete method implementations without omitting lines, using ellipses (`...`), or placeholder comments like `// implement here`.
  - Ensure the solution covers all algorithmic logic and helper routines completely.
- Increase Groq Vision `max_tokens` from `1500` to `2500` to prevent token cutoff on complex DSA implementations.

### 3. Polish Canvas Code Blocks in `markdownRenderer.tsx`
- Ensure code block presentation inside `MarkdownView` is modern, spacious, and displays all lines of code without cramping or inner scrollbars.
- Ensure syntax highlighting colors are vivid, readable against dark transparent backgrounds, and wrap safely on long lines.

  - Complete code requirements in prompt instructions.
  - Increased `max_tokens` (2500) in payload construction.
  - Strict sequence: Intuition -> Full C++ Code -> Complexity after code.
