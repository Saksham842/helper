# Plan 06-01: REA Security & Bundle Hygiene Audit

## Objective
Use the `# rea` MCP server tools to perform a static security audit on the compiled Vite renderer bundle (`apps/desktop/dist/`) and Electron main process bundle (`apps/desktop/dist-electron/`), verifying zero secret key leakage, safe IPC boundary hygiene, and no unintended global API exposure. Document findings and fix any surfaced issues. Write `06-REA-AUDIT.md`.

## Requirements Covered
- **STLTH-05**: Production bundle security and anti-detection hygiene verification.

## Tasks

### 1. Build Fresh Bundles for Inspection
- Run `pnpm --filter @ghostpilot/desktop build` to produce fresh `dist/` and `dist-electron/` artifacts.
- Confirm output artifacts exist:
  - `apps/desktop/dist/assets/` — Vite renderer bundle chunks
  - `apps/desktop/dist-electron/main/index.js` — Electron main process
  - `apps/desktop/dist-electron/preload/index.js` — Contextbridge preload

### 2. REA Bundle Analysis — Renderer (Secret Key Leak Check)
- Use `# rea` MCP tool `analyze_javascript_application` on `apps/desktop/dist/` to:
  - Scan all chunk files for patterns matching: `SUPABASE_SERVICE_ROLE_KEY`, `ANTHROPIC_API_KEY`, `sk-ant-`, `service_role`, any 40+ character hexadecimal or JWT-shaped strings not prefixed with `VITE_`.
  - Verify that only `VITE_SUPABASE_URL` and `VITE_SUPABASE_ANON_KEY` patterns appear in renderer chunks (these are intentionally public).
  - Identify any `process.env.ANTHROPIC_API_KEY` or `process.env.SUPABASE_SERVICE_ROLE_KEY` references that vite-plugin-electron may have inlined.
- Use `# rea` `export_web_scripts` to extract all inline script content from `apps/desktop/index.html` (the Electron entry point).
- Use `# rea` `recover_javascript_sources` on the dist bundle chunks to recover readable variable names from minified output and identify any suspicious constant strings.

### 3. REA Bundle Analysis — Preload & IPC Boundary
- Use `# rea` `analyze_javascript_application` on `apps/desktop/dist-electron/preload/index.js`:
  - Verify `contextBridge.exposeInMainWorld()` exposes ONLY the documented API surface:
    - `window.electronAPI.onTranscript`
    - `window.electronAPI.onAIAnswer`
    - `window.electronAPI.captureScreenshot`
    - `window.electronAPI.toggleVisibility`
    - `window.electronAPI.toggleClickThrough`
    - `window.electronAPI.authFromToken`
  - Confirm no `ipcRenderer` object, `require`, `__dirname`, or `process` is directly exposed to the renderer context.
  - Confirm no raw Node.js built-ins are accessible from the renderer.
- Use `# rea` `inspect_web_event_listeners` to identify any event listeners set up in the preload that might bridge unexpected channels.

### 4. REA Bundle Analysis — Main Process
- Use `# rea` `analyze_javascript_application` on `apps/desktop/dist-electron/main/index.js`:
  - Verify `nodeIntegration: false` and `contextIsolation: true` are set in `BrowserWindow` webPreferences.
  - Verify `webSecurity` is not set to `false`.
  - Check that all `ipcMain.handle()` channels have explicit input validation (no wildcard channel handlers).
  - Verify `setContentProtection(true)` call is present.

### 5. Fix Surfaced Issues
- If any secret key is found in the renderer bundle: investigate the Vite build config (`vite.config.ts`) for inadvertent `define` injections, add explicit exclusion, and re-build to confirm clean.
- If any IPC boundary violations are found: patch `preload/index.ts` to remove unsafe exposures and add defensive channel validation to `ipcMain.handle` handlers.
- If `webSecurity: false` or `nodeIntegration: true` is found in any BrowserWindow: remove immediately.

## Verification Criteria
1. `analyze_javascript_application` finds zero secret key patterns in renderer bundle.
2. Preload exposes only the documented `window.electronAPI.*` surface — no raw Node APIs.
3. Main process has `nodeIntegration: false`, `contextIsolation: true`, `webSecurity` not disabled.
4. `setContentProtection(true)` confirmed present in main process bundle.
5. `06-REA-AUDIT.md` written with all rows `PASS`.
